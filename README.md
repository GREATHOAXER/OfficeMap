# OfficeMap
Vibe Coding Project @ KFTC

사업장·층별 좌석과 동료의 재실 상태, 회의실 예약을 한 곳에서 보는 사내 서비스입니다.

## 폴더 구조

| 폴더 | 내용 |
|---|---|
| `db/` | 테이블 정의(`schema/`)와 목업 데이터(`seed/`) — PostgreSQL 16 |
| `server/` | API 서버 — Python FastAPI, uvicorn으로 실행 |
| `frontend/` | 화면 — Next.js 16 |
| `docs/design/` | 설계 문서 — [도면 편집 · 좌석 배치 편집](docs/design/floor-plan-and-seating.md) |
| `deploy/` | 서버 배포 설정 — 도커 compose(Caddy · 화면 · API), [AWS에 올리기](docs/deploy-aws.md) |

브라우저는 Next.js(3000번)에만 접속하고, Next.js가 `/api/...` 요청을 FastAPI(8000번)로 넘겨줍니다.

## 로컬에서 실행하기

준비물: Python 3.11 이상, Node.js 20.9 이상, PostgreSQL 16 + pgvector (Docker가 있으면 Docker로 대신)

### 1. DB 띄우기

**Docker가 있으면** (pgvector가 들어 있는 이미지)

```bash
docker compose up -d db
```

**PostgreSQL을 직접 설치했다면** 관리자 계정(postgres)으로 한 번만:

```sql
CREATE ROLE officemap LOGIN PASSWORD 'officemap';
CREATE DATABASE officemap OWNER officemap;
\c officemap
CREATE EXTENSION btree_gist;
CREATE EXTENSION vector;   -- pgvector 확장이 설치돼 있어야 함
```

### 2. API 서버 (uvicorn)

```bash
cd server
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp -n .env.example .env            # 처음 한 번만 (이미 있으면 그대로 둠). Windows: if not exist .env copy .env.example .env
python -m scripts.init_db          # 테이블 + 목업 데이터 넣기
uvicorn app.main:app --reload --port 8000
```

- http://localhost:8000/docs 에서 API를 바로 눌러 볼 수 있습니다.
- DB를 처음 상태로 되돌리려면 `python -m scripts.init_db --reset`

### 3. 화면 (Next.js)

다른 터미널에서:

```bash
cd frontend
npm install
cp -n .env.example .env.local      # 처음 한 번만 (이미 있으면 그대로 둠). Windows: if not exist .env.local copy .env.example .env.local
npm run dev
```

http://localhost:3000 에 접속하면 로그인 화면이 뜹니다.

### 내 PC를 ngrok으로 바깥에 공개하기

공개하는 것은 화면 서버(3000) 하나입니다. API(8000)는 화면 서버가 `/api`로 넘겨주므로 따로 공개하지 않습니다.
바깥에 보여 줄 때는 **빌드해서 띄우는 쪽**을 권합니다 (개발 서버보다 훨씬 빠르고 아래 설정도 필요 없음).

```bash
cd frontend
npm run build
npm start                          # http://localhost:3000
ngrok http 3000                    # 다른 터미널. 출력된 https://….ngrok-free.app 으로 접속
```

개발 서버(`npm run dev`)를 그대로 공개할 때는 **ngrok을 먼저 켜고 개발 서버를 켜세요**. 개발 서버가 켜질 때 이 PC의 ngrok
주소를 읽어 허용합니다 (터미널에 `개발 서버 외부 주소 허용: ….ngrok-free.dev`가 찍힘). 개발 서버를 먼저 켰다면 한 번 껐다 켜면 됩니다.
ngrok 말고 다른 주소(PC 이름, 사내 IP 등)로 열거나 자동으로 안 잡히면 `frontend/.env.local`에 호스트 이름을 넣고 개발 서버를 다시 켭니다.
개발 서버 터미널의 `개발 서버 외부 주소 허용:` 줄에 그 주소가 보이면 적용된 것입니다. 빌드(`npm run build`)는 `.env` 파일을 고치지 않습니다.
`.env.local`이 `.env`보다 우선이라, `.env.local`에 `DEV_ORIGINS=`(빈 값)가 있으면 `.env`에 적은 값은 무시됩니다.

```bash
DEV_ORIGINS=abcd-12-34-56.ngrok-free.dev     # 여러 개면 쉼표로. https://…/ 처럼 주소째 넣어도 됨
```

허용되지 않은 주소로 열면 Next.js 개발 서버가 개발용 연결(`/_next/…`)을 막아서 화면 스크립트가 돌지 않습니다.
로그인 버튼을 눌러도 로그인 화면이 다시 뜨기만 하고, 몇 초 뒤 화면 위에 "화면 스크립트가 붙지 않았습니다" 안내가 뜹니다
(개발 서버에서만). 이때 개발 서버 터미널에는 `Blocked cross-origin request … allowedDevOrigins` 경고가, uvicorn 창에는
`GET /api/auth/me 401`이 찍힙니다 (로그인 안 된 상태로 로그인 화면을 다시 그린 결과이고 원인은 위 설정).
uvicorn 창에 `POST /api/auth/login … 401`이 찍히면 그건 사번·비밀번호가 틀린 것입니다. ngrok 무료 주소는 처음 들어갈 때
ngrok 안내 화면이 한 번 뜨는데 "Visit Site"를 누르면 됩니다. 로그인 쿠키는 `COOKIE_SECURE=false` 그대로 https(ngrok)에서도 동작합니다.
로그인이 응답은 성공인데 실제로는 안 된 경우(중간의 안내 화면이 대신 답함, 브라우저가 로그인 쿠키를 저장하지 않음)는
로그인 화면이 말없이 다시 뜨지 않고 그 이유를 오류로 보여 줍니다.

### 목업 계정

비밀번호는 모두 `officemap1234` 입니다.

목업 데이터는 서울 본사 1F~10F(1F 로비, 2F 대강당, 3F 식당, 4F~9F 사무실, 10F 임원실), 13개 팀, 좌석 254석, 직원 196명입니다.
8F는 사람이 많은 층의 예시로, 도면 편집기 도면(실제 크기 책상 1.6 × 0.8 m)에 68석·54명(디지털혁신팀·AI플랫폼팀·앱개발팀)과
회의실 5개, 라운지·폰부스·수유실 같은 부대시설이 있습니다 (`db/seed/03_dense_floor.sql`, `server/scripts/gen_dense_floor.py`로 만듦).

### 관리자 페이지 (`/admin`)

주소창에 `/admin`(또는 `/admin/login`)을 직접 넣어 들어갑니다. 직원 화면과 관리자 페이지는 서로 넘어가는 링크가
없습니다(관리자라도 직원 화면에 관리자 입구가 보이지 않고, 관리자 페이지에도 직원 화면 링크가 없음). 직원 로그인과 **비밀번호가 따로**이고,
목업 관리자 비밀번호는 모두 `officemap-admin` 입니다 (직원 비밀번호 `officemap1234`로는 안 들어가짐).

**최종 관리자**: 관리자 ID `admin` / 비밀번호 `officemapking`. 사람이 아닌 시스템 계정이라 직원 화면·조직도·검색에 나오지 않고,
1~4단계 관리자를 모두 지정·편집하며 전사 관리자가 하는 일을 모두 합니다. 목업이 아니라 DB를 만들 때(`init_db --no-seed`도) 늘 생기므로,
**실제 서버에서는 처음 로그인한 뒤 계정 메뉴의 "관리자 비밀번호 변경"으로 바로 바꾸세요** (이 저장소에 비밀번호가 적혀 있습니다).
로그인 칸은 "사번"이지만 `admin`을 그대로 넣으면 됩니다. 최종 관리자 비밀번호를 5번 틀려 잠기면 30분 뒤 저절로 풀립니다.

| 사번 | 이름 | 관리자 권한 |
|---|---|---|
| admin | 최종 관리자 (시스템 계정) | 최종 관리자 · 전체 (비밀번호 `officemapking`) |
| 20090001 | 한도윤 부장 (총무팀) | 전사 관리자 · 전체 사업장 |
| 20120002 | 강지아 차장 (총무팀) | 사업장 관리자 · 서울 본사 |
| 20130003 | 정민호 차장 (IT운영팀) | 층 관리자 · 서울 본사 7F |
| 20150004 | 오서연 과장 (재무팀) | 구역 관리자 · 7F 재무팀 B구역 (층 관리자 승인 후 반영) |

**권한 부여·편집** (관리자 첫 화면 "관리자 권한 체계"의 "권한 부여", 관리자 목록의 "편집"):

- 최종 관리자는 1~4단계, 전사 관리자는 2~4단계, 사업장 관리자는 그 사업장의 층·구역 관리자, 층 관리자는 그 층의 구역 관리자를
  지정·편집·회수합니다. 같은 층에 층 관리자를 여러 명 둘 수 있고, 구역 관리자가 없으면 층 관리자가 그 구역 배치까지 맡습니다.
- 사람을 이름·사번으로 찾아 권한과 범위(사업장 → 층 → 팀 구역)를 고릅니다. 구역 관리자는 변경 반영 방식(즉시 / 층 관리자 승인 후)도.
  사업장 표의 층마다 "+ 층 관리자 지정"(구역 관리자를 줄 수만 있으면 "+ 구역 관리자 지정")으로 그 층을 미리 골라 엽니다.
- 관리자 계정이 없던 사람에게 권한을 주면 관리자 계정이 임시 비밀번호로 만들어져 한 번만 보입니다. 그 사람이 관리자 ID(사번)와
  임시 비밀번호로 들어오면 새 관리자 비밀번호부터 정합니다. "편집"에서 권한·범위·반영 방식을 바꾸고, 회수하고,
  관리자 비밀번호를 초기화합니다(잠금도 풀림, 그 사람의 권한을 모두 내가 다룰 수 있을 때만).
- 예: `admin`으로 들어가 한도현(20180010)에게 "층 관리자 · 서울 본사 · 6F"를 주고, 보여 준 임시 비밀번호로 한도현 관리자 로그인 →
  비밀번호 정하기 → 6F 배치 편집. 정민호(7F 층 관리자)로는 7F 구역 관리자만 줄 수 있습니다.

**사업장·층·조직도** (한도윤 = 전사 관리자, 최종 관리자도):

- 관리자 첫 화면의 "사업장 추가"로 예: 부산 센터를 만들고 "+ 층 추가"로 층을 만듭니다(놓을 자리로 층 버튼 순서).
  "층 고치기"에서 이름·용도·순서를 바꾸고, 좌석·회의실이 없는 층은 없앨 수 있습니다. 강지아(사업장 관리자)는 서울 본사의 층만.
- 왼쪽 메뉴 "조직도"(`/admin/org`)에서 부서 나무를 보고, 부서 추가·이름·위 부서 바꾸기·없애기, "다른 부서에서 데려오기",
  "새 직원 등록"(임시 비밀번호가 한 번 보임), 사람마다 옮기기·휴직·비밀번호 초기화·퇴사를 합니다. 다른 관리자는 보기만.
  조시우를 다른 팀으로 옮기면 7F 자리 배정이 끝나고 그 팀의 미배치 인원이 됩니다.

**좌석 배치 편집** (`/admin/seating`, 관리자 첫 화면의 "배치 편집"):

- 정민호(층 관리자)로 들어가 미배치 인원 한도현을 7F B-17 빈 자리로 끌어다 놓고 "반영하기" → 7F를 보고 있던
  직원 화면에 바로 "7F 자리 배치가 바뀌었어요", 한도현 화면에는 "내 자리가 바뀌었어요"가 뜹니다.
- 오서연(구역 관리자, 승인 후 반영)으로 들어가면 재무팀 B구역만 움직일 수 있고, 작성 중이던 "신규 입사자 배치"가
  있습니다. "층 관리자에게 승인 요청" → 정민호 화면의 요청 목록에 바로 뜨고 "검토"에서 승인·반려합니다.
  층 관리자 이상(사업장·전사·최종 관리자 포함)은 관리자 첫 화면의 **승인함**에서도 바로 승인·반려할 수 있습니다.
- "날짜 지정"으로 반영하면 그날 0시부터 바뀌고, 그 전에는 요청 목록에서 "예정 취소"할 수 있습니다.
- 휴대폰에서는 끌기 대신 미배치 인원을 누른 뒤 자리를 누릅니다.
- **팀 구역**: 정민호로 "+ 팀 구역 추가"(예: 데이터팀) → "팀 구역 지정" 도구로 공용 자율석 좌석을 네모로 묶고 반영하면
  직원 화면에 새 구역이 바로 그려집니다. 구역의 "고치기"에서 이름·색을 바꾸거나 구역을 없앨 수 있습니다.
  오서연은 "+ 구역 확장·변경 요청"으로 B구역을 넓혀 달라고 요청합니다.

**도면 편집** (`/admin/plans`, 관리자 첫 화면의 "도면 관리", 층 관리자 이상):

- 7F에는 목업 초안(v2)이 있어 바로 편집 화면이 열립니다. 다른 층은 "게시본으로 초안 만들기"·빈 도면·다른 층 복제·보관본에서
  시작을 고릅니다. 초안은 게시하기 전까지 직원 화면에 보이지 않고, 고치면 자동 저장됩니다.
- 왼쪽 도구로 벽·기둥·회의실·공간을 끌어서 그리고, 책상 묶음(1인·마주보기 6석·한 방향 4석·팀 섬 12석)은 누른 곳에 놓습니다.
  고른 요소는 끌어서 옮기고 손잡이로 크기를 바꾸며, 오른쪽에서 이름·정원·좌석 번호를 고칩니다. Delete·방향키·Ctrl+Z/Y·Ctrl+D.
- 앉은 사람이 있는 책상(B-16 등)을 지우거나 예약이 있는 소회의실 702를 지운 뒤 "도면 게시…"를 누르면 점검 화면에서
  그 사람의 새 자리(기본 미배치, "모두 추천 자리로")와 예약을 옮길 회의실(또는 취소)을 정하고 게시합니다.
  7F를 보고 있던 직원 화면에는 "도면이 새로 게시됐어요" 배너가 뜨고 5초 뒤 새 도면으로 바뀝니다.
- 정민호가 편집 중일 때 강지아로 같은 층을 열면 보기만 할 수 있고, "편집 넘겨받기"로 가져올 수 있습니다.
- 게시 점검에서 "날짜 지정"을 고르면 게시를 예약합니다(그날 0시에 서버가 게시). 바로 확인하려면 예약한 뒤
  `UPDATE floor_plans SET effective_at = now() WHERE status = 'SCHEDULED';`를 실행하고 1분 안에 직원 화면이 바뀌는지 봅니다.
- 요약 칸의 "도면 크기"로 층을 넓히거나 줄이고(요소도 같은 비율로 바꾸기 가능), 요소를 Ctrl+C 한 뒤 다른 층 도면에서 Ctrl+V로
  붙여 넣을 수 있습니다. 배치 화면·도면 편집 화면의 "내보내기"로 PNG·PDF를 만듭니다.
- "선 벽"으로 선을 그어 벽을 만들고(Shift: 45도), "주 출입구"·"출입구"를 그려 봅니다. 오른쪽에서 선 굵기(cm)·글자 크기(%)·굵게.
- B 묶음을 누르고 R을 누르면 책상이 90도 돌아갑니다(앉은 사람 그대로). 책상 폭·깊이(m)도 묶음마다 바꿉니다.
- Ctrl을 누르고 A·C 묶음을 누르거나 빈 곳에서 끌어 여러 개를 고른 뒤 함께 옮기고 "왼쪽" 맞추기를 해 봅니다.
- 트랙패드 핀치·Ctrl+휠로 확대하고, 눈금자와 "치수 보기"로 크기(m)를 확인합니다.
- **도면 파일로 시작**: 8F 시작 화면의 "도면 파일 고르기…"로 그림(PNG·JPG·WEBP)·PDF·엑셀(.xlsx)을 올립니다. PDF에 층이
  여러 쪽이면 글자에서 찾은 층 이름("8F"·"지하 1층")으로 쪽마다 층이 저절로 맞춰지고(직접 고르거나 "순서대로 층 맞추기"도),
  끌어서 도면 부분을, 축척(1:200)·가로 길이·"아는 길이로 맞추기"로 실제 크기를 정합니다. 찾은 벽·기둥·회의실·공간·책상이
  그림 위에 겹쳐 보이고, "N개 층 초안 만들기"를 누르면 층마다 초안이 생기며 원본 그림이 밑그림으로 깔립니다
  (도구 줄 "밑그림" 체크로 숨기기, "밑그림…"으로 자리·진하기·지우기). 이미 초안이 있는 층은 편집 화면의 "도면 파일 깔기…".

**팀 이사** (`/admin/moves`, 왼쪽 메뉴 "팀 이사"):

- 강지아(사업장 관리자)로 인사팀(7F C구역 5명)을 10F 비서석 구역 빈 자리 5석으로 옮겨 봅니다. 구역을 누르면 빈 자리를
  모두 고르고 "순서대로" 맞춰 줍니다. 날짜를 정하면 그날 0시에 함께 바뀌고, 10F나 7F 배치 화면 요청 목록에서 "예정 취소"로
  모두 되돌립니다.

서버는 하루 한 번 5년이 지난 이력을 지웁니다(`python -m scripts.purge_history --dry-run`으로 지울 개수만 볼 수 있음).

관리자 화면은 15분 쓰지 않으면 자동 로그아웃되고, 관리자 비밀번호를 5번 틀리면 관리자 계정만 잠깁니다
(직원 화면 로그인은 그대로). 직원 화면이든 관리자 페이지든 로그아웃하면 그 브라우저의 두 로그인이 모두 끝납니다.

로그인이 끊기면 로그인 화면이 이유를 알려 줍니다: 오래 쓰지 않음, 로그인 유지 시간(12시간) 지남, 관리자가 비밀번호를 초기화함,
다른 곳에서 비밀번호를 바꿈, 비밀번호를 여러 번 틀려 잠김, 휴직·퇴사 (`user_sessions.revoked_reason`, `/api/auth/me`의 `reason`).
다시 로그인하면 보던 화면으로 돌아갑니다. 비밀번호 변경 화면에서 현재 비밀번호를 틀린 것도 로그인 실패 횟수에 들어가
5번이면 계정이 잠깁니다.

목업 회의실 예약은 `init_db`를 실행한 날을 오늘로 잡고 만듭니다. 며칠 지나 예약표가 비어 보이면 다시 만드세요.

`frontend`의 `npm run dev`·`npm run build`는 먼저 pdf.js 파일(일꾼·글꼴)을 `frontend/public/pdfjs/`로 복사합니다
(`frontend/scripts/copy-pdfjs.mjs`). 사내망에서 빌드할 때는 npm 저장소(미러)에 `pdfjs-dist`·`exceljs`도 있어야 합니다.

잠긴 계정은 `python -m scripts.init_db --reset`으로 풀립니다. 저장소를 새로 받아 DB 구조나 목업이 바뀌었을 때도
같은 명령으로 다시 만드세요 (기존 데이터는 지워집니다).

## 서버에 올리기 (AWS)

화면(`frontend/Dockerfile`)과 API(`server/Dockerfile`)를 도커 이미지로 만들어 EC2 한 대에 띄우고, DB는 RDS PostgreSQL을 씁니다.
앞단의 Caddy가 `/api`는 FastAPI로, 나머지는 화면으로 보내고, 도메인을 넣으면 HTTPS 인증서도 저절로 받습니다.
AWS 계정 만들기부터 순서대로: [docs/deploy-aws.md](docs/deploy-aws.md)

```bash
cd deploy && cp .env.example .env   # DATABASE_URL 등 채우기
docker compose build
docker compose run --rm backend python -m scripts.check_db   # DB 접속 점검 (막히면 고칠 곳을 알려 줌)
docker compose run --rm backend python -m scripts.init_db
docker compose up -d
```

- `APP_ENV=production`인 서버에서는 `init_db --reset`(모든 테이블 지우기)이 막힙니다.
- 로컬 개발(`npm run dev`·`npm start`)은 그대로이고, 도커 빌드에서만 Next.js를 standalone(실행에 필요한 파일만)으로 빌드합니다.

## Claude Code 클라우드 세션에서 임시 공개하기 (데모용)

클라우드 세션의 컨테이너는 바깥에서 접속할 수 없어서 ngrok으로 임시 공개 주소를 만듭니다.
환경 설정에 환경 변수 `NGROK_AUTHTOKEN`과 네트워크 허용 도메인 `connect.ngrok-agent.com`을 넣은 뒤,
새 세션에서 아래를 실행하면 DB부터 화면까지 띄우고 공개 주소를 출력합니다.

```bash
bash scripts/cloud-demo.sh        # 끄기: bash scripts/cloud-demo.sh stop
```

공개 주소는 링크를 아는 누구나 접속할 수 있으니 목업 데이터로만 쓰고, 다 보면 끄세요.
